The script runner acts as the primary operational CLI entry point for developers and CI/CD pipelines to verify accounting engine accuracy against production historical backups.

### 2.2 CLI Interface Options
```bash
npx tsx scripts/verify-trial-balance-backup.ts [options]
```
- `--year <number>`: Target fiscal year to verify (default: `2024`).
- `--backup-dir <path>`: Path to backup directory (default: `C:\Users\ccarvajalino\OneDrive\H Plus\Contabilidad\Backup` or `process.env.BACKUP_DIR`).
- `--tolerance <number>`: Numerical float tolerance in COP (default: `0.01`).
- `--detailed`: Include third-party detail rows in comparison summary (default: `true`).
- `--json`: Output report as raw JSON (useful for log collectors and CI artifacts).

### 2.3 Execution Flow Diagram & Step Sequence
1. **Pre-flight Backup Directory Baseline Snapshot**:
   - Record `mtimeMs`, `size`, and filename list for all files in `Backup` directory.
   - Verify directory exists and target benchmark file exists.
2. **Benchmark Excel Extraction**:
   - Call `parseBenchmarkTrialBalance(filePath)` using in-memory buffer (`readBackupFileBuffer`).
   - Extract structured `BenchmarkTrialBalanceRow[]`.
3. **Trial Balance Engine Execution**:
   - Query DB / calculate engine `getTrialBalance({ year, month: 12, includeThirdParty: true })`.
4. **Comparator Execution**:
   - Run `compareTrialBalances(generatedReport, benchmarkRows, { tolerance: 0.01 })`.
5. **Post-execution Read-Only Verification**:
   - Re-check baseline snapshot against current directory state.
   - Verify 0 files mutated and 0 new files created in `Backup` directory.
6. **Report Rendering & Exit Code**:
   - Print formatted console summary table.
   - Exit with `process.exit(0)` if clean pass, or `process.exit(1)` if any discrepancy or read-only failure occurred.

## 4. Read-Only Infrastructure Guard Verification Mechanics

### 4.1 Threat Model for Backup Directory
The directory `C:\Users\ccarvajalino\OneDrive\H Plus\Contabilidad\Backup` resides in a cloud-synced OneDrive directory. Any of the following actions violate system constraints:
- Opening file with write/append flags (`w`, `w+`, `a`, `r+`).
- Creating intermediate output files, temporary files, logs, or reports in `Backup`.
- Mutating `mtime`, `ctime`, or file size of historical `.xlsx` files.

### 4.2 Multi-Layer Safety Guard Implementation

#### Layer 1: In-Memory Read-Only Buffer Access (`readBackupFileBuffer`)
Files are opened exclusively with mode `'r'` using `fs.openSync(path, 'r')`. Content is read into a Node `Buffer` in RAM and the file descriptor is immediately closed. Excel parser libraries (`exceljs` or `xlsx`) parse the RAM `Buffer` rather than the physical disk file handle.

#### Layer 2: Pre/Post Baseline Snapshot Verification
Before any processing starts, take a directory snapshot:
```typescript
export interface DirectorySnapshot {
  timestamp: number;
  files: Map<string, { mtimeMs: number; size: number }>;
}

export function takeDirectorySnapshot(dirPath: string): DirectorySnapshot {
  const map = new Map<string, { mtimeMs: number; size: number }>();
  const entries = fs.readdirSync(dirPath, { recursive: true });
  for (const entry of entries) {
    const fullPath = path.join(dirPath, entry.toString());
    if (fs.existsSync(fullPath) && fs.statSync(fullPath).isFile()) {
      const stat = fs.statSync(fullPath);
      map.set(fullPath, { mtimeMs: stat.mtimeMs, size: stat.size });
    }
  }
  return { timestamp: Date.now(), files: map };
}
```

#### Layer 3: No-New-Files Validation (`verifyNoNewFilesCreated`)
After execution, compare current `fs.readdirSync(dirPath)` against baseline. If `currentFiles.length !== baselineFiles.length` or if any new file path exists, throw `ReadOnlyViolationError`:
```typescript
export function verifyBackupDirectoryUnchanged(
  dirPath: string,
  baseline: DirectorySnapshot
): { passed: boolean; violations: string[] } {
  const violations: string[] = [];
  const currentEntries = fs.readdirSync(dirPath, { recursive: true });
  const currentFiles = new Set<string>();

  for (const entry of currentEntries) {
    const fullPath = path.join(dirPath, entry.toString());
    if (fs.existsSync(fullPath) && fs.statSync(fullPath).isFile()) {
      currentFiles.add(fullPath);
      const stat = fs.statSync(fullPath);
      const baseStat = baseline.files.get(fullPath);

      if (!baseStat) {
        violations.push(`NEW FILE CREATED IN BACKUP DIR: ${fullPath}`);
      } else if (stat.mtimeMs !== baseStat.mtimeMs || stat.size !== baseStat.size) {
        violations.push(`FILE MUTATED IN BACKUP DIR: ${fullPath}`);
      }
    }
  }

  // Check for deleted files
  for (const [baseFile] of baseline.files.entries()) {
    if (!currentFiles.has(baseFile)) {
      violations.push(`FILE DELETED FROM BACKUP DIR: ${baseFile}`);
    }
  }

  return {
    passed: violations.length === 0,
    violations,
  };
}
```

## 5. Assertion Mechanics & Discrepancy Detection

### 5.1 Field Comparisons & Tolerance Rules
For each matched account/third-party row, compare 4 key financial fields:
1. `saldo_inicial` (Initial Balance)
2. `debito` (Period Debits)
3. `credito` (Period Credits)
4. `saldo_final` (Final Balance)

Float tolerance rule:
$$\Delta = |\text{Generated} - \text{Benchmark}|$$
$$\text{IsMatch} = \Delta \le 0.01\text{ COP}$$

### 5.2 Discrepancy Classification
- `BALANCE_MISMATCH`: Account code / third party match, but one or more balances differ by $> 0.01$ COP.
- `MISSING_IN_GENERATED`: Account row exists in benchmark Excel, but missing from generated trial balance.
- `MISSING_IN_BENCHMARK`: Account row exists in generated trial balance, but missing from benchmark Excel.
- `READONLY_VIOLATION`: Backup directory modified or path traversal attempt detected.

### 5.3 Match Statistics Structure (`MatchStats`)
```typescript
export interface MatchStats {
  totalBenchmarkRows: number;
  totalGeneratedRows: number;
  matchedRows: number;
  exactMatches: number; // delta == 0.00
  toleranceMatches: number; // 0 < delta <= 0.01
  balanceMismatches: number; // delta > 0.01
  missingInGenerated: number;
  missingInBenchmark: number;
  maxDeltaCOP: number;
  readOnlyGuardPassed: boolean;
}
```

### 6.2 Exit Code Rules
- **Exit Code 0**: 
  - `readOnlyGuardPassed === true`
  - `balanceMismatches === 0`
  - `missingInGenerated === 0`
  - `missingInBenchmark === 0`
- **Exit Code 1**:
  - Any discrepancy exceeding tolerance ($\Delta > 0.01$ COP)
  - Missing benchmark or missing generated accounts
  - `ReadOnlyViolationError` triggered
  - Benchmark Excel file not found or parsing error
